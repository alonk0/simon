# תוכנית – Milestone 4: מסך אודות מלא ואיפוס נתונים

**מקורות:** `MILESTONES.md` (Milestone 4), `PRD.md` (§3 זרימות ״מעבר למסך אודות״ ו״איפוס נתונים״, FR-01, FR-05, FR-06, Edge Cases, §176–177), `ARCHITECTURE.md` (§2.2, §2.4, זרימת אודות, §2.10, ADR-3), `DESIGN.md` (§1.4, §1.5, §2.3, §2.4, §2.5), `wireframes.png` ו־`mockups.png` (מסך ״אודות״), `style-guide.png` (Card, Modal / Dialog, כפתור אדום לאישור פעולה הרסנית).

**מטרה:** מסך ״אודות״ מציג נתונים אמיתיים מהאחסון המקומי — שיא אישי, סטטיסטיקות והיסטוריה (מהחדש לישן, DD.MM.YYYY) — ומאפשר ״איפוס נתונים״ דרך Dialog אישור/ביטול, עם עדכון מיידי של המסך. אין מסך נוסף, אין שינוי במשחק עצמו.

- אין תלויות חדשות, אין `.env`, חשבונות או שירותים חיצוניים.

- אין שינוי ב־Data Model או במפתח האחסון (`simon:results:v1`); משתמשים ב־`load`/`clear` הקיימים וב־`computeStatistics` (לפי ADR-3).

## 2. לוגיקה טהורה – `src/game/history.ts`

```ts
type HistoryItem = { date: string; roundsText: string; resultText: 'ניצחון' | 'הפסד' };

formatDate(iso: string): string            // local device time → "10.04.2025" (padStart 2)
roundsLabel(n: number): string             // "שלב אחד" for 1, otherwise "<n> שלבים" (incl. "0 שלבים")
toHistoryItems(games): HistoryItem[]       // reversed copy (newest first); does not mutate input
```

- **סדר:** הרשומות נשמרות לפי סדר הוספה (ARCHITECTURE §2.4), ולכן ״מהחדש לישן״ = היפוך המערך. לא ממיינים לפי תאריך, כדי ששני משחקים באותו יום יישארו בסדר הנכון.
- **תאריך:** לפי שעון המכשיר (`getDate`/`getMonth`/`getFullYear`), בלי שעה ובלי משך משחק.
- **אחוז הצלחה:** כבר מחושב ב־`computeStatistics` (`Math.round`, `null` כשאין משחקים) — מוצג כ־`38%` או ״אין נתונים״.

## 3. מסך ״אודות״ – `src/ui/aboutScreen.ts`

`createAboutScreen(nav, results)` מחזיר `{ element, render }`. `render()` קורא `results.load()` ומעדכן את הכרטיסים (במקום הערכים הקבועים של היום).

סדר הכרטיסים לפי DESIGN §1.4 וה־Wireframes (ללא שינוי בשני הראשונים):

1. **על המשחק** — טקסט קיים.
2. **הוראות משחק** — רשימה קיימת.
3. **שיא אישי** — ערך בולט (`personalBest`); כשאין משחקים: ״אין נתונים״ (כמו היום).
4. **סטטיסטיקות** — משחקים שהסתיימו (`totalGames`), ניצחונות (`wins`), אחוז הצלחה (`38%` / ״אין נתונים״). מספרים מבודדים ב־`dir="ltr"`.
5. **היסטוריית משחקים** — רשימה (`<ol>`), כל שורה: תוצאה (ניצחון/הפסד) · שלבים · תאריך, בסידור של ה־Wireframe (תוצאה מימין, תאריך משמאל). המשחק האחרון ראשון. מצב ריק: ״עדיין אין משחקים שהסתיימו״ (קיים).
6. **כפתור ״איפוס נתונים״** — כפתור כהה ברוחב מלא בתחתית (`btn--dark`, כבר קיים), עכשיו פעיל.

**מצבי אחסון חריגים** (ARCHITECTURE §2.4 — ״להציג מצב נתונים לא זמין/לא תקין בעברית״):
- `unavailable` (אחסון חסום): הודעה קצרה ״לא ניתן לקרוא נתונים שמורים במכשיר זה״; הכרטיסים מציגים מצב ריק (״אין נתונים״), בלי מספרים בדויים.
- `invalid` (נתונים פגומים): הודעה ״הנתונים השמורים אינם תקינים. ניתן לאפס אותם.״; מצב ריק בכרטיסים. הנתונים **לא** נדרסים אוטומטית; איפוס מאושר מוחק את המפתח וחוזר למצב ריק.
- ההודעה מוצגת בכרטיס ״היסטוריית משחקים״ (אין כרטיס או מסך חדש).

**גלילה:** העמוד כולו גולל אנכית (כבר כך היום); אין גובה קבוע לרשימה ואין דחיסת כרטיסים.

## 4. Dialog ״איפוס נתונים״

שכבה בתוך מסך ״אודות״ (לא מסך נוסף — PRD §176, DESIGN §1.5), לפי ה־Style Guide (Modal / Dialog):

- אלמנט `<dialog>` מובנה של הדפדפן, נפתח ב־`showModal()` (Overlay כהה, מיקוד בתוך החלון, מקש Escape = ביטול).
- תוכן: אייקון ״!״ אדום עגול, כותרת ״איפוס נתונים״, טקסט ״האם אתה בטוח שברצונך לאפס את כל הנתונים?״, שני כפתורים: ״ביטול״ (Secondary) ו״איפוס״ (אדום מודגש — DESIGN: `red` = ״אישור פעולה הרסנית״). כפתור ה־X שבדוגמה לא נדרש — ״ביטול״ ממלא את התפקיד.
- המיקוד ההתחלתי על ״ביטול״ (הבחירה הבטוחה).
- **ביטול / Escape:** סוגר את החלון, לא נוגע באחסון.
- **איפוס:** `results.clear()` (`removeItem` למפתח האפליקציה בלבד), סגירת החלון ו־`render()` מיידי → שיא ״אין נתונים״, 0 משחקים, 0 ניצחונות, אחוז ״אין נתונים״, היסטוריה ריקה. המיקוד חוזר לכפתור ״איפוס נתונים״.
- אם `clear()` נכשל (אחסון חסום): החלון נסגר והודעה ״איפוס הנתונים נכשל״; לא מוצג דיווח כוזב על הצלחה.
- יציאה מ״אודות״ (כפתור ״בית״) כשהחלון פתוח לא אפשרית בגלל המודאליות; אם הוא פתוח ונעשה ניווט — נסגר ללא שינוי.

## 5. חיבור – `src/main.ts`

- `createAboutScreen(nav, results)` מקבל את אותו Repository שמשמש את סיום המשחק.
- ב־`nav.onNavigate`: כשנכנסים ל״אודות״ → `about.render()` (זרימת אודות ב־ARCHITECTURE: קריאה → חישוב → הצגה). כך תוצאה חדשה מופיעה מיד.
- ביטול משחק פעיל ביציאה מהבית נשאר כמו היום (`controller.cancel()` ללא שמירה); חזרה לבית מציגה `idle`.

## 6. עיצוב – `src/styles/components.css`

- **היסטוריה:** שורות בעמודה אחת עם קו מפריד דק (`light-gray`, כמו `stat-row`), שלוש עמודות (תוצאה · שלבים · תאריך), Body 16px; תאריך ב־`dir="ltr"`.
- **הודעת נתונים:** טקסט Caption 14px בצבע `muted-text`.
- **Dialog:** משטח לבן, גבול כהה דק, פינות מעוגלות, צל — אותה שפה כמו `.modal` הקיים; `::backdrop` כהה כמו `.overlay`. שני הכפתורים זה לצד זה ברוחב שווה.
- **כפתור ״איפוס״ אדום:** מחלקה חדשה `btn--danger` (רקע `red`, טקסט לבן מודגש).
- מרווחים בכפולות 8px; RTL ויישור לימין בכרטיסים; ללא גלילה אופקית ב־360–430px.

## 7. בדיקות

**Vitest – `tests/history.test.ts`:**
- `formatDate` — ריפוד אפסים (`05.04.2025`), תאריך לפי שעון מקומי, ללא שעה.
- `toHistoryItems` — המשחק האחרון ראשון; המערך המקורי לא משתנה; רשימה ריקה → `[]`.
- `roundsLabel` — 0, 1, 6, 10; `resultText` לניצחון/הפסד.
- (קיים) `statistics.test.ts` — אחוז מעוגל (9/24 → 38) ו־`null` כשאין משחקים.

**Playwright – `e2e/about.spec.ts`** (Pixel 7, Touch; נתונים נזרעים ישירות ל־`localStorage` לפני טעינה):
- **מצב ריק:** אין נתונים → שיא ״אין נתונים״, 0/0/״אין נתונים״, ״עדיין אין משחקים שהסתיימו״.
- **היסטוריה וסטטיסטיקות:** 3 משחקים זרועים (כולל ניצחון) → מספרים ואחוז נכונים, הסדר מהחדש לישן, תאריכים ב־DD.MM.YYYY, אין שעה (`:` לא מופיע בשורות).
- **משחק אמיתי מופיע:** הפסד במשחק → ״אודות״ → השורה העליונה היא המשחק הזה.
- **ניווט:** יציאה ל״אודות״ באמצע משחק לא מוסיפה שורה ולא משנה שיא; חזרה ל״בית״ → ״לחץ על התחל״ וכפתור ״התחל״ גלוי.
- **איפוס — ביטול:** פתיחת Dialog → ״ביטול״ → הנתונים והמסך ללא שינוי, האחסון ללא שינוי.
- **איפוס — אישור:** ״איפוס״ → המסך מתעדכן מיד למצב ריק; המפתח נמחק; לאחר רענון — עדיין ריק.
- **נתונים פגומים:** הודעת ״אינם תקינים״, המשחק והמסך לא קורסים; איפוס מאושר מחזיר למצב ריק.
- **גלילה:** עם 30 משחקים זרועים — אין גלילה אופקית (`scrollWidth <= clientWidth`), וכפתור האיפוס נגיש בגלילה.
- כל בדיקות Milestone 1–3 הקיימות ממשיכות לעבור.

**בדיקה ידנית (שלי בזמן הבנייה):** צילום מסך של ״אודות״ ושל ה־Dialog בגודל טלפון, והשוואה ל־`wireframes.png`, `mockups.png` ו־`style-guide.png`.

## 8. ADR לתיעוד ב־ARCHITECTURE.md בזמן הבנייה

- **ADR-4: Dialog איפוס באלמנט `<dialog>` מובנה** — מספק Overlay, מיקוד ו־Escape בלי קוד נוסף; סדר ההיסטוריה נגזר מסדר ההוספה (היפוך) ולא ממיון לפי תאריך; הצגת מצבי ״לא זמין/לא תקין״ בכרטיס ההיסטוריה.

## 9. מיפוי ל־Definition of Done

| תנאי DoD | איך נבדק |
|---|---|
| ״אודות״ מציג ערכים התואמים למשחקים השמורים; מספר המשחקים ואחוז ההצלחה נכונים | Vitest (`statistics`) + Playwright עם נתונים זרועים |
| כל פריט: תאריך DD.MM.YYYY, שלבים ותוצאה; האחרון ראשון; בלי שעה/משך | Vitest (`history`) + Playwright |
| התוכן קריא ונגלל במובייל, בלי דחיסה ובלי מסכי משנה | Playwright (30 משחקים, ללא גלילה אופקית) + צילום מסך |
| ״איפוס נתונים״ פותח Dialog; ביטול לא משנה; אישור מאפס היסטוריה, שיא ומדדים, גם אחרי רענון | Playwright |
| יציאה ממשחק פעיל ל״אודות״ לא מוסיפה תוצאה ולא משנה שיא; חזרה לבית = `idle` | Playwright |
| בדיקות Playwright להיסטוריה, נתונים ריקים, ניווט ואיפוס עוברות | `npm run test:e2e` (וגם `npm test`, `npm run build`) |

## 10. מחוץ להיקף במילסטון זה
